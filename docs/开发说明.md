# 开发与维护

## 模块与加载顺序

HTML 入口使用普通脚本，按顺序共享编辑状态；目前不采用构建器或 ES module，以支持直接通过 `file://` 打开。

1. `src/editor-core.js`：步骤模型、表单描述、迁移、校验、Ren'Py 生成。
2. `src/app.js`：主状态、撤销、基本交互、轻量导入导出、目录写入。
3. `src/story-editor.js`：长篇目录、分页、多选、搜索、工程包、草稿数据库和分支检查。
4. `src/visual-editor.js`：舞台、素材数据库、快照、单步动画与拖动。
5. `src/styles.css`：界面样式与响应式布局。

保持入口文件名与数据库名称稳定，避免用户草稿无法定位。变更工程数据格式时，应同步修改迁移、导入验证和测试。显示名称、预览行为与生成器语义应一同更新。

## 环境

- Windows + Microsoft Edge：使用与浏览器测试。
- Node.js 20+：运行测试；`npm install` 安装 package.json 中固定版本的 playwright-core。无需下载 Chromium，测试使用已有 Edge。
- Python 3.10+：打包与 Ren'Py 辅助工具；全部使用标准库。
- Ren'Py SDK：仅引擎 lint 与试玩需要，不能由网页代替。

可选环境变量：

| 变量 | 用途 |
| --- | --- |
| `EDGE_PATH` | 测试浏览器路径；未设置时检测系统常见 Edge 路径 |
| `GVE_ROOT` | 测试要打开的工程目录，可用于验证解压后的发布包 |
| `GVE_TEST_OUTPUT` | 测试产物目录，默认 tests/artifacts |
| `RENPY_SDK` | 辅助工具默认 SDK 目录 |
| `RENPY_PROJECT` | 辅助工具默认游戏工程目录 |

所有测试使用独立浏览器资料，不使用日常浏览器的草稿与素材。未设置 SDK、游戏路径时，辅助工具从用户主目录开始选择，不绑定开发者电脑的路径。

## 检查与测试

```powershell
npm run check
npm test
```

三个套件分别覆盖基本功能、舞台和长篇工作流；截图、工程样例、ZIP 与报告生成在 `tests/artifacts/`。`regression.cjs` 会自动创建包含静音 WAV 的独立 Ren'Py 测试工程，不依赖旧测试残留。

运行引擎检查：

```powershell
python tools/renpy_check.py --sdk 'D:\你的RenPySDK' --project 'tests/artifacts/renpy-fixture' --lint --report 'tests/artifacts/renpy-lint.txt'
```

修改后应运行对应测试；影响模型、导入或生成器时运行全部套件。新增 UI 的结果必须通过实际操作测试，不能仅以生成函数输出代替。

## 发布

```powershell
python scripts/build_release.py
```

默认输出 `dist/GalgameVisualEditor-版本.zip` 和 `.zip.sha256`。脚本使用白名单收集文件，排除历史备份、缓存、依赖目录、个人文件与测试产物；检查 HTML 本地资源引用，并验证 ZIP CRC 及每个文件的 SHA-256。发布包内包含 `BUILD-MANIFEST.json`。

将 ZIP 解压到新的目录，用 `GVE_ROOT` 指向它运行测试，确认没有依赖原目录。发布程序包之前还应提醒使用者通过 `.rpe` 单独导出浏览器内的个人工程。

## 格式与维护原则

使用 UTF-8，JavaScript 两空格、Python 四空格；遵循根目录 `.editorconfig`。本轮按模块重整目录和运行路径，未进行大规模业务逻辑重写；已有紧凑函数可以在后续局部修改时逐步展开。

不要在代码、测试或文档中写入某位使用者的绝对路径。不要把浏览器草稿、导入图片或真实游戏放入源码包。普通用户修改 `examples/` 中示例后，应另存为自己的工程文件。
